# 管理

管理员入口位于助手下方，依次提供插件管理、用户管理、SMTP服务、服务与公告。顶级管理员仍绑定唯一账户ID，不能被任免、停用或删除。只有顶级管理员可以任免普通管理员。

## 插件提交与商城

开发者先将正式插件包发布到自己的 GitHub Release，再在“插件管理 → 开发插件”填写发行地址和 SHA-256。客户端先下载文件，再把原始字节上传给服务器作内存校验；也可选择已下载的同一 `.nous-plugin.json` 文件。网页受 GitHub 跨域或网络限制时使用文件选择方式。服务器检查摘要、仓库、插件结构、协议及最低宿主，保存提交、manifest和下载元数据，不保存发行包或运行模块。

普通开发者及普通管理员提交后进入审核。审核员使用自己的客户端重新取得同一文件，并在服务器校验它与原提交的摘要和声明一致。顶级管理员提交会直接发布到商城。官方标签独立由管理员设置，不由作者、提交角色或本地安装决定；更新保留已有官方标签，禁止降级覆盖。

普通开发者每小时最多尝试提交12次，失败也计入；普通管理员与顶级管理员不受这项提交频率限制。摘要、协议、命名空间、重复待审版本与禁止降级等校验继续生效。

管理员可上架、下架、设置官方标签和删除商城插件。删除需要应用内确认，只移除商城条目，保留审核历史与用户已安装的数据；同插件尚在等待审核的旧提交会被驳回，避免误操作重新上架。重新发布必须重新提交。

安装插件、运行模块、更新程序及网页文件下载展示真实字节进度。总量未知时不显示估计百分比；校验成功后才安装或保存文件。网页无法跨域读取 GitHub 文件时，可改用外部浏览器下载，其进度由浏览器管理；应用不模拟无法读取的进度。

## SMTP服务

“注册账号”和“找回密码”分别编辑主题及正文。正文必须保留 `{{code}}`，可使用 `{{minutes}}`、`{{appName}}`。预览不会发送邮件；连接凭证不返回页面。既有自定义邮件模板保留为注册模板，找回密码采用独立默认模板。

验证码发送请求携带 `purpose=register` 或 `purpose=reset`，新验证码绑定用途，不能跨用途兑换。旧版本已发出、尚未过期的验证码在原十分钟有效期内兼容。

## 应用内确认

删除消息、对话、助手、文档以及开发权限确认均使用应用内对话框。Windows的本机工具授权、PowerShell命令及开发代理逐次工具授权也使用同一界面；默认焦点为取消，授权请求绑定账户且只能消费一次，超时、关闭应用或任务中止均按拒绝处理。文件/目录选择、系统安装与UAC仍由操作系统负责。

## 服务与账户

停服限制普通用户和游客，管理员仍可登录管理。公告仅通知已登录非管理员账户。账户修改、密码重置及管理员权限边界保持原有规则。
