# 1.0.0 版本与分发

Nous 从本次正式版重新采用 1.0.0，发布纪元为 1。Android 显示版本 1.0.0，内部版本码 1000000 高于历史 20201，沿用已有签名和应用标识，可覆盖升级并保留数据。Windows 沿用应用标识，只发布 NSIS 安装版。

主仓库 [liveldy/Nous](https://github.com/liveldy/Nous) 仅放门户、使用说明、协议文档、发布清单，不上传主程序源码。客户端安装包放在主仓库 Releases。插件各用自己的仓库和 Releases；需要开源的依赖同时提供完整对应源码与许可证。

`releases.json` 和 `plugins.json` 是签名信封：`signed` 为 UTF-8 JSON 的 base64，`signature` 为 RSA SHA-256 PKCS#1 v1.5 签名的 base64。客户端内置公钥验证；发布私钥保存在维护者本地。签名内容含 schema、纪元、版本、发布日期、更新说明、平台资源 URL、字节数与 SHA-256。版本更新仅允许同纪元的更高正式版本，安装前重新读取并验证清单和文件，不自动执行未校验程序。系统安装界面仍由用户确认。

服务器只运行网站后端和必要运行时，保存用户数据；不承载客户端安装包、便携包、插件包或这些包的源码归档。旧下载路径跳转 GitHub，未知归档返回 404。新发行脚本仅从本地白名单目录推送门户与插件源码，安装包直接上传 GitHub；不得再执行历史服务器分发脚本。

发布步骤：完成检查 → 本机构建签名 APK 与 Windows 安装版 → 在各自仓库创建草稿 Release → 上传安装包及校验信息 → 校验远程大小和哈希 → 发布 Release → 签名更新目录与版本清单 → 部署网站和后端 → 验证原 IP、账户数据与下载跳转 → 删除服务器旧分发文件。发布产物不包含 Design.md、环境变量、用户数据、密钥或主应用源码。
